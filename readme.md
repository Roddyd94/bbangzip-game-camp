# 01주차 — Pong — 공·패들 충돌과 점수

## 1. 이번 주차의 주제

공·패들의 이동과 충돌을 통해 입력·갱신·출력으로 이어지는 게임 루프를 직접 만듭니다.

## 2. 사전 지식

아래 개념·검색어를 따라 개인적으로 학습하고, 확인 질문에 작은 계산·그림·코드로 답할 수 있는지 살펴봅니다. 학습 노트 제출은 필요하지 않습니다. 설계 패턴은 이해를 돕는 수단이며 특정 구조를 강제하지 않습니다.

| 분야 | 학습할 개념·검색어 | 구현과의 연결 | 스스로 확인할 질문 |
|---|---|---|---|
| 수학·물리 | 2D 벡터, 속도, 위치 += 속도 × dt, 반사 | 실수 위치를 유지하고 벽 충돌 때 해당 축 속도의 부호를 바꿉니다. | 초당 10칸인 공의 0.1초 이동량은? X축 반사 후 vx와 vy는? |
| 컴퓨터 과학 | 고정·가변 시간 간격, 샘플링 오차 | 프레임 수와 이동량을 분리하고 큰 dt로 패들을 건너뛰는 문제를 이해합니다. | 매 프레임 1칸 이동하면 PC마다 속도가 달라지는 이유는? |

## 3. 구현 환경 세팅

환경: **C++ / Windows 콘솔(CMD), ASCII 렌더링**. 이 절은 개인 Fork 복제 후 수행할 설정입니다. 현재 브랜치에는 문서와 `.gitignore`만 있고 소스·프로젝트·Starter Kit는 없습니다. 아래 설정을 마친 뒤 프로젝트와 기능을 구현해야 빌드할 수 있습니다. 사용할 도구의 정확한 버전은 시작 전에 합의합니다.

1. Visual Studio의 **C++를 사용한 데스크톱 개발** 워크로드와 Windows SDK를 설치합니다.
2. Fork 폴더 안에 C++ 콘솔 앱 프로젝트를 만듭니다. 솔루션·프로젝트 파일이 Fork 안에 저장되는지 확인하고 별도 Git 저장소를 중첩 생성하지 않습니다.
3. 프로젝트 속성에서 C++17 이상, 빌드 플랫폼 x64로 설정합니다. 기본 표준 라이브러리 외 외부 패키지는 필요하지 않습니다.
4. 기본 콘솔 프로그램을 빌드·실행한 뒤 주차별 로직을 작성합니다. 실제 사용한 컴파일러·SDK 버전을 프로젝트 설정에 맞춰 확인합니다.

설정 참고: [Visual Studio C++ 개발](https://learn.microsoft.com/en-us/cpp/get-started/?view=msvc-170).

## 4. 기획안과 구현 목표

### 기획 규칙과 범위

- 보드 80×24칸, 좌·우 패들 각각 W/S와 위/아래 방향키, R 재시작, Esc 종료를 기본안으로 합니다. 키 입력 방식은 Windows 콘솔 구현에 맞게 바꿀 수 있습니다.
- 반사는 속도 성분의 부호를 바꾸는 기본 방식으로 충분합니다. 패들이 화면 밖으로 나가지 않게 합니다.
- 연속적인 득점을 막기 위해 득점 처리 후 공 위치와 라운드 상태를 함께 갱신합니다.

**선택 확장:** CPU 패들, 반사 각도·속도 변화. 완료 조건에는 포함하지 않습니다.
**이번 범위에서 제외:** 물리 엔진, 네트워크 멀티플레이, 원본 리소스 복제.

### 구현할 기능

1. 공과 두 패들을 ASCII로 표시하고 키보드로 패들을 움직입니다.
2. 경과 시간에 따라 공을 이동하고 위·아래 벽과 패들에 닿으면 반사합니다.
3. 공이 좌·우 경계를 벗어나면 상대 점수를 한 번만 올리고 중앙에서 다음 라운드를 시작합니다.
4. 재시작 시 공·패들 위치와 점수를 초기화합니다.

### 목표 동작 명세

기획에 따른 기대 결과이며 실제 확인 결과가 아닙니다. 구현하면서 직접 확인하면 되고 별도 검증 보고서는 필요하지 않습니다.

| ID | 확인 방법 | 기대 결과 |
|---|---|---|
| P01 | 공을 위쪽 벽으로 이동 | 공이 화면 안에서 아래 방향으로 반사 |
| P02 | 패들을 공 경로에 배치한 뒤 충돌 | 공의 수평 이동 방향 반전 |
| P03 | 공이 왼쪽 경계를 벗어나게 함 | 오른쪽 점수만 1 증가, 공 중앙 복귀 |
| P04 | 득점 후 R 입력 | 점수 0:0, 공·패들 초기 위치 |

## 5. 프로젝트 Fork와 세팅 후 빌드

### Fork와 작업 브랜치

1. 원본 GitHub 저장소를 개인 계정으로 Fork합니다. 실제 원본 주소가 정해지면 아래 URL 자리표시자를 바꿉니다.
2. PowerShell에서 다음 명령을 실행합니다. `<...>` 전체를 실제 URL로 바꾸세요. 이미 복제했다면 clone과 remote add를 반복하지 않습니다.

```powershell
git clone <개인-Fork-URL> game-system-lab
cd game-system-lab
git remote add upstream <원본-저장소-URL>
git fetch upstream
git switch -c work/01 upstream/week/01-pong
```

`origin`은 개인 Fork, `upstream`은 원본입니다. 원본에서 주차 브랜치를 가져오므로 Fork에 기본 브랜치만 복사되어 있어도 됩니다. 이미 만든 작업 브랜치로 돌아갈 때는 `git switch work/01`을 사용합니다. 다음으로 3절의 환경을 구성하고 4절의 기능을 구현합니다.

### 빌드와 실행

1. 3절에서 생성하거나 가져온 실제 솔루션 파일을 Visual Studio로 엽니다. 프로젝트를 아직 만들지 않았다면 빌드할 대상이 없습니다.
2. 실행할 프로젝트를 시작 프로젝트로 지정하고 **Debug / x64**를 선택한 뒤 **빌드 → 솔루션 빌드**를 실행합니다.
3. **디버깅하지 않고 시작(Ctrl+F5)**으로 실행합니다. 상태를 추적할 때는 F5로 디버깅하고 중단점에서 값을 확인합니다.
4. 출력 경로는 프로젝트 속성의 출력 디렉터리에서 확인합니다. 소스·솔루션·프로젝트 설정을 함께 관리하고 `.vs/`·중간 생성물·실행 파일은 기존 `.gitignore`로 제외합니다.
5. 콘솔에서 4절의 조작·입력을 사용해 목표 동작을 확인합니다. 입력 대기 중 정지한 상태와 비정상 종료를 구분합니다.
