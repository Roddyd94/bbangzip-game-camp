# 03주차 — 레이싱 게임 — 랩·구간 기록

## 1. 이번 주차의 주제

운전 가능한 짧은 트랙에서 랩·구간 기록 시스템을 완성합니다. 차량 물리·조작·트리거 감지는 제공하며, 직접 작성한 통과 순서와 시간 규칙을 HUD에 연결합니다.

### 훈련 상황

주행 가능한 차량·트랙과 체크포인트 통과 이벤트가 제공된다는 전제에서, 기록 시스템을 담당하는 상황입니다. 통과 순서와 시각을 받아 유효한 랩·구간 시간을 계산하고, 중복 통과·체크포인트 누락·차량 복귀를 처리해 HUD와 기록에 연결하는 훈련입니다. 차량 조작과 독립된 이벤트 기반 시스템을 만들고, 운전 없이도 기록 규칙을 재현하는 경험을 목표로 합니다.

## 2. 사전 지식

아래 개념·검색어를 따라 개인적으로 학습하고, 확인 질문에 작은 계산·그림·코드로 답할 수 있는지 살펴봅니다. 학습 노트 제출은 필요하지 않습니다. 설계 패턴은 이해를 돕는 수단이며 특정 구조를 강제하지 않습니다.

| 분야 | 학습할 개념·검색어 | 구현과의 연결 | 스스로 확인할 질문 |
|---|---|---|---|
| 수학·물리 | 시간차·단위 변환·구간 합 | 구간은 인접 시각의 차이, 랩은 종료−시작입니다. 차량 동역학은 필요하지 않습니다. | 0초 시작·3초 CP1·7초 완주의 구간과 랩은? |
| 컴퓨터 과학 | 유한 상태 기계·이벤트 순서 | 시작 전·주행·종료 상태와 허용 이벤트를 정합니다. | CP1 누락과 중복 통과를 어떻게 구분할까요? |
| 게임 엔진 원리 | Collider 트리거·방향 필터·게임 시간과 실제 시간 | 제공 어댑터가 트리거를 통과 이벤트로 바꿉니다. 콜라이더 구성·차량 물리는 구현하지 않습니다. | timeScale이 0이어도 실제 시간은 흐를까요? |
| 알고리즘·자료구조 | 체크포인트 배열·다음 인덱스·기록 목록 | 현재 기대하는 체크포인트를 기준으로 순서를 검사합니다. | CP가 늘어날 때 조건문 대신 어떤 데이터로 순서를 표현할까요? |
| 설계 패턴 | 상태 전이·시계 의존성 주입 | 이벤트 시각을 인자로 받으면 실제 대기 없이 결과를 확인할 수 있습니다. | 7초 랩을 실제 7초 기다리지 않고 어떻게 재현할까요? |
| 운영체제 | 단조 시간·Update/FixedUpdate·메인 스레드 | 제공 시각의 기준을 확인하고 물리 콜백 시점과 화면 갱신 시점을 구분합니다. | 물리 프레임 수로 시간을 세면 설정에 따라 기록이 달라질까요? |

## 3. 구현 환경 세팅

환경: **Unity / C# / 제공 레이싱 씬**.

**제공 상태:** 현재는 문서·`.gitignore`만 있습니다. 아래 Starter Kit 구성·인터페이스·경로는 제공 목표 명세이며 구현된 파일이 아닙니다. 실제 세션은 운영자가 핵심 로직이 비어 있는 실행 가능한 Starter Kit를 배포한 뒤 시작합니다. 참여자에게 주변 시스템 제작을 과제로 넘기지 않습니다.

### 제공할 시스템과 참여자 구현 범위

| 구분 | 범위 |
|---|---|
| 운영자 제공 | 차량 조작·물리, 시작선·체크포인트가 있는 트랙, 카메라, 방향을 구분한 통과 이벤트, 단조 경과 시간 공급, 기록 HUD, 차량 복귀, 이벤트 재생 도구 |
| 참여자 구현 | 시작·구간·완주 상태, 체크포인트 순서·중복 검사, 구간·랩 시간, 유효 랩·기록 갱신, 기록 초기화 |

1. 배포된 Starter Kit의 `ProjectSettings/ProjectVersion.txt`에 맞는 Unity 에디터를 Hub에서 설치하고 Windows 빌드 지원 모듈을 추가합니다. 실제 버전·패키지 잠금 파일은 운영자가 배포 시 고정합니다.
2. 5절에 따라 Fork·복제한 저장소 루트를 Hub에 추가합니다. `Assets/`, `Packages/`, `ProjectSettings/`가 있는 폴더가 프로젝트 루트입니다. 빈 프로젝트를 새로 만들지 않습니다.
3. 패키지 복원을 기다린 뒤 제공할 `Assets/Scenes/Racing.unity`를 열고 Play합니다. 기본 조작·카메라·표시와 디버그 입력이 동작하고, 미완성 코어 때문에 목표 기능만 비어 있는지 확인합니다.
4. 제공 어댑터가 참조하는 `Assets/Scripts/Study/`의 코어와 DTO를 확인합니다. 아래 인터페이스 이름은 설계 예시이며 배포 Kit의 실제 선언을 기준으로 구현합니다. Rigidbody·콜라이더·카메라·UI를 다시 만들지 않습니다.

환경 참고: [Unity Hub 프로젝트 관리](https://docs.unity.com/en-us/hub/projects).

## 4. 기획안과 구현 목표

### 제공 코드와 핵심 코드의 연결

다음은 Starter Kit가 충족해야 할 계약입니다. 화면·물리·입력 제공 코드가 핵심 정답을 대신 구현하지 않도록 구분합니다.

- 제공 어댑터가 `GatePassed(gateId, timestamp, crossingId)`를 전달합니다. StartFinish와 CP1을 구분하며 차량 전진 방향으로 통과한 이벤트만 공급합니다. timestamp는 주행 세션 기준 초 단위 실수이고 감소하지 않습니다.
- 참여자는 `LapState`에 다음 체크포인트·현재 진행 상태·구간 시간·완료 랩·최고 기록·유효성 사유를 보관합니다. 제공 HUD는 반환한 상태를 표시하고 시간 공급기는 화면 갱신용 현재 시각도 제공합니다.
- 시작선 첫 통과는 주행 시작, 다음 CP1 후 시작선 통과는 유효 완주입니다. 시작선을 다시 지나도 CP1이 없으면 무효 완주로 종료합니다. 다음 정방향 시작선 통과에서 새 랩을 시작합니다.
- 같은 crossingId의 중복 전달은 무시합니다. 이미 처리한 CP1의 재통과는 첫 구간 시각을 유지합니다. 역주행 방향 판정은 제공 측 책임이고, 체크포인트 순서 판단은 참여자 책임입니다.
- 제공 차량 복귀 버튼은 위치만 복구합니다. 참여자 코어는 복귀 요청으로 현재 랩을 무효화하며 기존 완료 기록은 유지합니다. 전체 Reset은 현재 상태와 완료·최고 기록을 함께 지웁니다.
- 0초 시작→3초 CP1→7초 완주 같은 이벤트 재생을 제공해 운전 실력이나 물리 오차 없이 기록기를 확인합니다.

### 기획 규칙과 범위

- 최소 코스는 StartFinish → CP1 → StartFinish입니다. 실제 차량으로 통과하거나 제공 재생 도구로 동일 이벤트를 보냅니다.
- 시간 기준은 제공 단조 경과 시간입니다. 이 회차에는 일시정지를 두지 않고 게임 시간 배율을 1로 고정합니다.
- 무효 랩은 유효 기록·최고 기록에 넣지 않습니다. 다음 랩 시작 시 현재 랩만 초기화하고 기존 완료 기록은 유지합니다.
- UI 업데이트·차량 물리·트리거 콜라이더 구성은 제공하며 참여자가 다시 구현하지 않습니다. 다중 체크포인트·기록 파일 저장은 선택입니다.

### 구현할 기능

1. 제공 통과 이벤트로 시작 전·주행·완료 상태를 갱신합니다.
2. 지정 순서와 중복을 검사하고 구간·랩 시간을 계산합니다.
3. 유효 랩만 기록하고 최고 랩을 갱신해 HUD에 전달합니다.
4. 차량 복귀 시 현재 랩 무효화와 전체 Reset을 구분해 처리합니다.

### 목표 동작 명세

제공 장면 또는 입력 재생 도구로 아래 동작을 확인합니다. 별도 검증 보고서는 필요하지 않습니다. 아래는 기대 결과이며 실제 실행 결과가 아닙니다.

| ID | 확인 방법 | 기대 결과 |
|---|---|---|
| L01 | 재생 도구: 0초 시작선 → 3초 CP1 → 7초 시작선 | 구간 3초·4초, 유효 랩 7초 |
| L02 | 시작선 → CP1 없이 시작선 | 무효 랩 표시, 유효 기록에 추가하지 않음 |
| L03 | 시작 전 CP1 이벤트 | 주행 시작·기록 추가 없음 |

| L07 | 주행 중 차량 복귀 | 현재 랩 무효, 기존 완료 기록 유지 |
| L08 | 같은 crossingId 이벤트 중복 전달 | 시간·진행 상태 중복 반영 없음 |

## 5. 프로젝트 Fork와 세팅 후 빌드

### Fork와 작업 브랜치

1. 운영자가 Starter Kit를 배포한 원본 저장소를 Fork합니다. 현재 문서 전용 상태에서는 빌드할 대상이 없으므로, 프로젝트 제공 뒤 아래 절차를 진행합니다.
2. PowerShell 명령의 `<...>` 전체를 실제 URL로 바꿉니다. 이미 복제했다면 clone·remote add는 반복하지 않습니다.

```powershell
git clone <개인-Fork-URL> game-system-lab
cd game-system-lab
git remote add upstream <원본-저장소-URL>
git fetch upstream
git switch -c work/03 upstream/week/03-lap-timing
```

`origin`은 개인 Fork, `upstream`은 원본입니다. 기존 작업 브랜치에서는 `git switch work/03`을 사용합니다. 이후 3절로 환경을 확인하고 4절의 핵심 코드를 구현합니다.

### 빌드와 실행

1. 제공 에디터 버전으로 저장소 루트를 열고 `Assets/Scenes/Racing.unity`에서 Play합니다. 제공 씬·스크립트를 그대로 사용하며 비어 있는 핵심 코어를 완성합니다.
2. Unity 6의 **File → Build Profiles**(이전 버전은 **Build Settings**)에서 Windows 대상을 선택하고 제공 씬이 빌드 목록에 포함·활성화되어 있는지 확인합니다.
3. **Build And Run**으로 저장소 루트의 `Builds/Windows/`에 출력합니다. 실행 파일과 함께 생성된 데이터 폴더 등 출력 전체를 유지합니다.
4. 실제 플레이와 제공 디버그 입력 양쪽에서 4절의 목표 동작이 같은 코어를 통해 반영되는지 확인합니다.

`Assets/`의 `.meta`, `Packages/`, `ProjectSettings/`는 함께 관리합니다. `Library/`, `Temp/`, `Builds/`는 `.gitignore`로 제외합니다. 위 씬 경로는 제공 목표이며 현재 파일이 존재한다는 뜻은 아닙니다.
