# 01주차 — Pong — 공·패들 충돌과 점수

## 1. 이번 주차의 주제

준비된 창·입력·렌더러 위에서 공의 연속 이동·충돌·득점 시스템을 구현합니다. 공과 패들의 움직임을 실수 좌표로 계산하고 픽셀 기반 화면에서 바로 확인합니다.

## 2. 사전 지식

아래 개념·검색어를 따라 개인적으로 학습하고, 확인 질문에 작은 계산·그림·코드로 답할 수 있는지 살펴봅니다. 학습 노트 제출은 필요하지 않습니다. 설계 패턴은 이해를 돕는 수단이며 특정 구조를 강제하지 않습니다.

| 분야 | 학습할 개념·검색어 | 구현과의 연결 | 스스로 확인할 질문 |
|---|---|---|---|
| 수학·물리 | 2D 벡터, 속도, 위치 += 속도 × dt, 반사 | 실수 위치를 유지하고 벽 충돌 때 해당 축 속도의 부호를 바꿉니다. | 초당 10칸인 공의 0.1초 이동량은? X축 반사 후 vx와 vy는? |

## 3. 구현 환경 세팅

환경: **C++17 이상 / SFML 3 / Windows 2D 창**.

**제공 상태:** SFML 3.1.0 헤더·라이브러리·DLL과 기본 창·입력·시계·도형 표시를 구성했습니다. 현재는 정지된 초기 화면과 코어 호출 경계가 동작하는 기본 세팅입니다. `src/main.cpp`는 제공 기반, `src/GameCore.cpp`의 TODO는 참여자 구현 영역입니다. 점수 UI·승패 화면·전체 스냅샷 계약 등 아래의 완전한 Starter Kit 명세는 아직 모두 구현되지 않았습니다.

### 제공할 시스템과 참여자 구현 범위

| 구분 | 범위 |
|---|---|
| 운영자 제공 | 창 생성·종료, 프레임 시계, 키 상태 읽기, 공·패들·점수 표시, 공통 시작·재시작 UI, CMake·SFML 의존성 설정 |
| 참여자 구현 | 공·패들 위치 갱신, 벽·패들 충돌과 반사, 이탈 득점, 라운드·재시작 상태 |

1. Visual Studio의 C++ 데스크톱 개발과 CMake 도구, Windows SDK를 설치합니다. Windows x64 / MSVC / C++17 구성이며 SFML 3.1.0 의존성은 저장소에 포함되어 다운로드하지 않습니다.
2. Fork·복제한 저장소에서 아래 빌드 명령을 실행합니다. VS 개발자 PowerShell에서 cmake를 사용할 수 있어야 합니다.
3. src/main.cpp의 입력 수집→코어 갱신→스냅샷 표시 흐름을 확인하고 src/GameCore.cpp의 TODO를 구현합니다. 창 초기화·SFML 링크 설정은 직접 작성하지 않습니다.

## 4. 기획안과 구현 목표

### 제공 코드와 핵심 코드의 연결

다음은 Starter Kit가 충족해야 할 계약입니다. 화면·물리·입력 제공 코드가 핵심 정답을 대신 구현하지 않도록 구분합니다.

- 제공 루프는 `Update(dt, input)`에 초 단위 경과 시간과 좌·우 패들 방향, 재시작 요청을 전달합니다. 입력은 키 이벤트 횟수가 아닌 현재 눌림 상태로 제공합니다.
- 참여자는 위치·속도·점수·라운드 상태가 담긴 `GameSnapshot`을 갱신합니다. 제공 렌더러는 이 값을 읽어 그리기만 하며 충돌·득점을 대신 계산하지 않습니다.
- 재시작 버튼·키는 제공하지만 상태를 초기화하는 `Reset()`의 내용은 참여자가 작성합니다.

### 기획 규칙과 범위

- 화면 800×600 픽셀, 좌표 원점은 좌상단, x는 오른쪽·y는 아래쪽을 기본안으로 합니다. 논리 좌표는 실수이며 표시할 때 문자 칸으로 양자화하지 않습니다.
- 좌·우 패들은 W/S·위/아래 방향키, R 재시작, Esc 종료입니다. 패들은 화면 밖으로 이동하지 않습니다.
- 패들 폭·높이와 공 반지름은 제공 설정에서 읽습니다. 공은 위·아래 벽과 패들에서 기본 반사하고 좌·우 이탈은 득점으로 처리합니다.
- 득점은 한 번만 반영하고 다음 라운드에서 공을 중앙에 놓습니다. CPU 패들·반사 각도 변화는 선택입니다.

### 구현할 기능

1. dt와 입력 상태를 이용해 공·패들 위치를 갱신합니다.
2. 벽·패들 충돌을 판정하고 겹침을 해소하며 이동 방향을 바꿉니다.
3. 좌·우 이탈 시 상대 점수를 한 번만 올리고 라운드를 초기화합니다.
4. Reset()에서 위치·속도·점수·진행 상태를 초기화합니다.

### 목표 동작 명세

제공 장면 또는 입력 재생 도구로 아래 동작을 확인합니다. 별도 검증 보고서는 필요하지 않습니다. 아래는 기대 결과이며 실제 실행 결과가 아닙니다.

| ID | 확인 방법 | 기대 결과 |
|---|---|---|
| P01 | 공을 위쪽 벽으로 이동 | 실수 좌표를 유지하며 공이 화면 안에서 아래 방향으로 반사 |
| P02 | 패들을 공 경로에 배치한 뒤 충돌 | 공의 수평 이동 방향 반전 |
| P03 | 공이 왼쪽 경계를 벗어나게 함 | 오른쪽 점수만 1 증가, 공 중앙 복귀 |
| P04 | 득점 후 R 입력 | 점수 0:0, 공·패들 초기 위치 |

## 5. 프로젝트 Fork와 세팅 후 빌드

### Fork와 작업 브랜치

1. 운영자가 Starter Kit를 배포한 원본 저장소를 Fork합니다. 현재 기본 세팅은 빌드 가능하며 핵심 게임 로직은 TODO로 남아 있습니다.
2. PowerShell 명령의 `<...>` 전체를 실제 URL로 바꿉니다. 이미 복제했다면 clone·remote add는 반복하지 않습니다.

```powershell
git clone <개인-Fork-URL> game-system-lab
cd game-system-lab
git remote add upstream <원본-저장소-URL>
git fetch upstream
git switch -c work/01 upstream/week/01-pong
```

`origin`은 개인 Fork, `upstream`은 원본입니다. 기존 작업 브랜치에서는 `git switch work/01`을 사용합니다. 이후 3절로 환경을 확인하고 4절의 핵심 코드를 구현합니다.

### 빌드와 실행

Windows x64 MSVC 개발 환경에서 저장소 루트를 기준으로 실행합니다.

```powershell
cmake -S . -B build -A x64
cmake --build build --config Debug
.\build\bin\Debug\StudyGame.exe
```

DLL은 빌드 후 실행 파일 옆으로 자동 복사됩니다. 기본 화면의 도형은 정지해 있으며, 이동·충돌·점수 로직은 참여자가 구현해야 합니다. Esc 또는 창 닫기는 제공됩니다. R 요청은 코어까지 전달되지만 Reset의 게임 상태 복원은 TODO입니다.

기본 렌더링·라이브러리 로드 확인:

```powershell
ctest --test-dir build -C Debug --output-on-failure
```

이 확인은 출력 폴더의 startup.png를 생성하며 게임 규칙의 정답 여부는 검사하지 않습니다. Release도 같은 구성에서 `--config Release`로 빌드할 수 있습니다. third_party의 배포 의존성은 보관하고 build 출력·IDE 캐시는 제외합니다.
