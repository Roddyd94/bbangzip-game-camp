# 02주차 — 볼링 게임 — 프레임별 점수 계산

게임 전체를 복제하기보다 핵심 시스템 하나를 설계·구현하고 설명하는 스터디입니다. **현재 이 브랜치는 과제 안내만 제공하며 소스·에셋·Starter Kit는 포함하지 않습니다.**

## 목표와 환경

- 환경: **C++ / Windows 콘솔(CMD)**
- 핵심 개념: 규칙 모델링, 상태 전이, 스트라이크·스페어, 경계값 검증
- 도구의 정확한 버전은 주제 시작 전에 합의하고, 본인 README에는 사용 버전과 실행 방법만 간단히 적습니다.
- 기본 진행 기간은 1주이며 시작일·마감일·발표일은 참여자 합의 후 Discord에 공지합니다.

## 필수 구현

1. 핀 수를 입력받아 유효한 투구 기록을 저장합니다.
2. 10프레임 점수를 계산하고 스트라이크·스페어 보너스를 반영합니다.
3. 마지막 프레임의 추가 투구를 처리하고 게임 종료 후 입력을 거부합니다.
4. 범위를 벗어난 핀 수나 남은 핀보다 큰 투구는 기록에 넣지 않고 다시 입력받습니다.

## 규칙과 범위 기본안

- 투구당 0~10핀입니다. 1~9프레임은 최대 2회 투구하되 스트라이크면 다음 프레임으로 넘어갑니다.
- 스트라이크는 다음 2회 투구, 스페어는 다음 1회 투구를 보너스로 더합니다. 보너스 투구가 남은 프레임은 점수 미확정으로 표시해도 됩니다.
- 10프레임은 스트라이크면 2회, 스페어면 1회 추가 투구합니다. 추가 투구는 새 프레임을 만들지 않습니다.
- 10프레임 첫 투구가 스트라이크인 경우 핀을 다시 세웁니다. 둘째도 스트라이크면 다시 세우고, 아니면 셋째는 둘째 투구 후 남은 핀 범위입니다.

**선택 확장:** 프레임별 점수판, 자동화 단위 테스트. 완료 조건에는 포함하지 않습니다.
**이번 범위에서 제외:** 3D 물리, 레인 렌더링, 실제 볼링 조작.

## 핵심 동작 확인

아래 상황을 직접 확인하면 됩니다. 별도 검증 보고서는 필요 없으며, 확인한 결과와 남은 문제를 핵심 설명에 한두 줄로 적습니다. 아래 표는 기대 결과이고 실제 실행 결과가 아닙니다.

| ID | 확인 방법 | 기대 결과 |
|---|---|---|
| B01 | 20회 모두 0핀 | 0점 |
| B02 | 각 프레임 9핀·0핀을 10회 | 90점 |
| B03 | 5핀·5핀을 10프레임, 추가 5핀 | 150점 |
| B04 | 12회 연속 스트라이크 | 300점, 추가 입력 거부 |
| B05 | 새 게임에서 8핀 다음 5핀 | 둘째 입력 거부, 기존 [8] 유지 |
| B06 | 10프레임에서 10핀·7핀 다음 4핀 | 셋째 입력 거부, 0~3핀만 허용 |

## 작업 방법

1. 원본 저장소를 개인 계정으로 Fork하고 로컬에 복제합니다. 원본 주소를 `upstream`으로 등록합니다. 원격 저장소가 공개되면 실제 주소를 사용합니다.
2. 이 주차 브랜치에서 개인 작업 브랜치를 만듭니다. 다음 명령은 원본을 `upstream`으로 등록한 뒤 실행합니다.

```sh
git fetch upstream
git switch -c work/02 upstream/week/02-bowling
```

3. 각자 구현하고 핵심 동작을 확인합니다. 작업 중 Discord에서 질문·화면 공유·토론할 수 있습니다.
4. 코드를 커밋해 개인 Fork에 올리고, 코드·실행 방법·시연·핵심 설명을 README 하나에 모읍니다. 이미 만든 브랜치로 돌아갈 때는 `git switch work/02`를 사용합니다.

```sh
git add <공유할-소스와-문서>
git commit -m "Implement 02-bowling study"
git push -u origin work/02
```

## 가벼운 결과 공유

필수 공유물은 다음 세 가지입니다. **추가 보고서·슬라이드·상세 회고는 필요하지 않습니다.**

- 코드와 간단한 실행 방법: 필요한 도구 버전, 프로젝트 열기·빌드·실행 순서, 조작법.
- 짧은 시연: 일반 점수와 스트라이크 300점 결과를 보여주는 콘솔 캡처.
- 핵심 설명 3~5줄: 구현 내용, 선택한 방법과 이유, 확인한 동작과 남은 한계.

### 복사할 공유 양식

```text
[02주차 / 볼링 게임] 이름
- 코드·실행 방법: <개인 Fork의 작업 브랜치 링크>
- 시연: <이미지·영상 또는 콘솔 결과 위치>
- 핵심 설명: <구현 내용 / 선택 이유 / 확인 결과·한계, 3~5줄>
```

### 작성 예시

아래는 작성법을 보여주는 가상 예시이며 실제 구현·검증 결과가 아닙니다.

```text
[02주차 / 볼링 게임] 민수
- 코드·실행 방법: 개인 Fork의 work/02 브랜치 README
- 시연: README에 첨부한 콘솔 캡처
- 핵심 설명: 입력 기록과 점수 계산을 분리해 같은 투구로 로직을 확인했습니다. 스트라이크 300점과 스페어 150점을 확인했습니다. 마지막 프레임의 입력 검증은 별도로 다뤘습니다.
```

Discord에는 위 자료를 모아 둔 README 링크만 올려도 됩니다. 미완성이면 현재 결과와 막힌 점을 공유합니다. 외부 코드·에셋을 가져왔다면 출처·사용 조건을, AI 도움을 받았다면 도움받은 범위와 직접 확인한 내용을 짧게 덧붙입니다.

## 발표

발표 5분 + 질의응답 5분을 기본으로 **시연 → 핵심 구현과 선택 이유 → 확인 결과·한계**를 이야기합니다. 불참 시에는 기존 결과 게시글로 대체하고 필요한 설명만 보완합니다. 별도 대체 발표 자료는 필수가 아닙니다.

## 저장소에 포함할 것

소스, 솔루션·프로젝트 파일 또는 빌드 설정, 직접 만든 시연 자료를 관리합니다. 사용자별 IDE 설정과 컴파일 결과는 `.gitignore`로 제외합니다.
빌드 결과물·캐시·비밀 키는 올리지 않습니다. 새 환경에서 실행에 필요한 파일은 제외하지 않습니다.
