# 01주차 — Pong — 공·패들 충돌과 점수

게임 전체를 복제하기보다 핵심 시스템 하나를 설계·구현하고 설명하는 스터디입니다. **현재 이 브랜치는 과제 안내만 제공하며 소스·에셋·Starter Kit는 포함하지 않습니다.**

## 목표와 환경

- 환경: **C++ / Windows 콘솔(CMD), ASCII 렌더링**
- 핵심 개념: 게임 루프, 좌표·속도, 충돌 판정, 상태 갱신
- 도구의 정확한 버전은 주제 시작 전에 합의하고, 본인 README에는 사용 버전과 실행 방법만 간단히 적습니다.
- 기본 진행 기간은 1주이며 시작일·마감일·발표일은 참여자 합의 후 Discord에 공지합니다.

## 필수 구현

1. 공과 두 패들을 ASCII로 표시하고 키보드로 패들을 움직입니다.
2. 경과 시간에 따라 공을 이동하고 위·아래 벽과 패들에 닿으면 반사합니다.
3. 공이 좌·우 경계를 벗어나면 상대 점수를 한 번만 올리고 중앙에서 다음 라운드를 시작합니다.
4. 재시작 시 공·패들 위치와 점수를 초기화합니다.

## 규칙과 범위 기본안

- 보드 80×24칸, 좌·우 패들 각각 W/S와 위/아래 방향키, R 재시작, Esc 종료를 기본안으로 합니다. 키 입력 방식은 Windows 콘솔 구현에 맞게 바꿀 수 있습니다.
- 반사는 속도 성분의 부호를 바꾸는 기본 방식으로 충분합니다. 패들이 화면 밖으로 나가지 않게 합니다.
- 연속적인 득점을 막기 위해 득점 처리 후 공 위치와 라운드 상태를 함께 갱신합니다.

**선택 확장:** CPU 패들, 반사 각도·속도 변화. 완료 조건에는 포함하지 않습니다.
**이번 범위에서 제외:** 물리 엔진, 네트워크 멀티플레이, 원본 리소스 복제.

## 핵심 동작 확인

아래 상황을 직접 확인하면 됩니다. 별도 검증 보고서는 필요 없으며, 확인한 결과와 남은 문제를 핵심 설명에 한두 줄로 적습니다. 아래 표는 기대 결과이고 실제 실행 결과가 아닙니다.

| ID | 확인 방법 | 기대 결과 |
|---|---|---|
| P01 | 공을 위쪽 벽으로 이동 | 공이 화면 안에서 아래 방향으로 반사 |
| P02 | 패들을 공 경로에 배치한 뒤 충돌 | 공의 수평 이동 방향 반전 |
| P03 | 공이 왼쪽 경계를 벗어나게 함 | 오른쪽 점수만 1 증가, 공 중앙 복귀 |
| P04 | 득점 후 R 입력 | 점수 0:0, 공·패들 초기 위치 |

## 작업 방법

1. 원본 저장소를 개인 계정으로 Fork하고 로컬에 복제합니다. 원본 주소를 `upstream`으로 등록합니다. 원격 저장소가 공개되면 실제 주소를 사용합니다.
2. 이 주차 브랜치에서 개인 작업 브랜치를 만듭니다. 다음 명령은 원본을 `upstream`으로 등록한 뒤 실행합니다.

```sh
git fetch upstream
git switch -c work/01 upstream/week/01-pong
```

3. 각자 구현하고 핵심 동작을 확인합니다. 작업 중 Discord에서 질문·화면 공유·토론할 수 있습니다.
4. 코드를 커밋해 개인 Fork에 올리고, 코드·실행 방법·시연·핵심 설명을 README 하나에 모읍니다. 이미 만든 브랜치로 돌아갈 때는 `git switch work/01`를 사용합니다.

```sh
git add <공유할-소스와-문서>
git commit -m "Implement 01-pong study"
git push -u origin work/01
```

## 가벼운 결과 공유

필수 공유물은 다음 세 가지입니다. **추가 보고서·슬라이드·상세 회고는 필요하지 않습니다.**

- 코드와 간단한 실행 방법: 필요한 도구 버전, 프로젝트 열기·빌드·실행 순서, 조작법.
- 짧은 시연: 패들 충돌과 득점 장면을 보여주는 10~30초 영상 또는 콘솔 캡처.
- 핵심 설명 3~5줄: 구현 내용, 선택한 방법과 이유, 확인한 동작과 남은 한계.

### 복사할 공유 양식

```text
[01주차 / Pong] 이름
- 코드·실행 방법: <개인 Fork의 작업 브랜치 링크>
- 시연: <이미지·영상 또는 콘솔 결과 위치>
- 핵심 설명: <구현 내용 / 선택 이유 / 확인 결과·한계, 3~5줄>
```

### 작성 예시

아래는 작성법을 보여주는 가상 예시이며 실제 구현·검증 결과가 아닙니다.

```text
[01주차 / Pong] 민수
- 코드·실행 방법: 개인 Fork의 work/01 브랜치 README
- 시연: README에 첨부한 시연 영상
- 핵심 설명: 좌표와 속도를 분리해 공 이동을 처리했습니다. 왼쪽 이탈 시 오른쪽 점수만 오르고 공이 중앙으로 돌아오는 것을 확인했습니다. 빠른 공의 충돌 누락은 남은 한계입니다.
```

Discord에는 위 자료를 모아 둔 README 링크만 올려도 됩니다. 미완성이면 현재 결과와 막힌 점을 공유합니다. 외부 코드·에셋을 가져왔다면 출처·사용 조건을, AI 도움을 받았다면 도움받은 범위와 직접 확인한 내용을 짧게 덧붙입니다.

## 발표

발표 5분 + 질의응답 5분을 기본으로 **시연 → 핵심 구현과 선택 이유 → 확인 결과·한계**를 이야기합니다. 불참 시에는 기존 결과 게시글로 대체하고 필요한 설명만 보완합니다. 별도 대체 발표 자료는 필수가 아닙니다.

## 저장소에 포함할 것

소스, 솔루션·프로젝트 파일 또는 빌드 설정, 직접 만든 시연 자료를 관리합니다. 사용자별 IDE 설정과 컴파일 결과는 `.gitignore`로 제외합니다.
빌드 결과물·캐시·비밀 키는 올리지 않습니다. 새 환경에서 실행에 필요한 파일은 제외하지 않습니다.
