# 03주차 — 레이싱 게임 — 랩·구간 기록

게임 전체를 복제하기보다 핵심 시스템 하나를 설계·구현하고 설명하는 스터디입니다. **현재 이 브랜치는 과제 안내만 제공하며 소스·에셋·Starter Kit는 포함하지 않습니다.**

## 목표와 환경

- 환경: **C++ / Windows 콘솔(CMD)**
- 핵심 개념: 시간 측정, 이벤트 기반 기록, 상태 관리, 유효 랩 판정
- 도구의 정확한 버전은 주제 시작 전에 합의하고, 본인 README에는 사용 버전과 실행 방법만 간단히 적습니다.
- 기본 진행 기간은 1주이며 시작일·마감일·발표일은 참여자 합의 후 Discord에 공지합니다.

## 필수 구현

1. 시작·체크포인트·결승선 이벤트를 키보드 입력으로 발생시킵니다.
2. 시작 전·주행 중·완료 상태를 구분하고 랩과 구간 시간을 계산합니다.
3. 체크포인트 순서를 지킨 랩만 유효 기록으로 남깁니다.
4. 재시작 시 진행 상태·현재 시간·기록을 초기화합니다.

## 규칙과 범위 기본안

- 최소 코스는 시작선 → CP1 → 결승선입니다. S 시작, C 체크포인트, F 결승선, R 재시작, Esc 종료를 기본안으로 합니다.
- 주행 중 결승선을 통과했지만 CP1이 없으면 무효 랩으로 종료합니다. 시작 전 이벤트는 무시하고 이유를 표시합니다. 중복 CP1은 첫 시각을 유지합니다.
- 실행 중에는 단조 증가 시계를 사용하고, 검증 시에는 0·3·7초처럼 지정한 시각을 넣을 수 있는 구조를 권장합니다.
- 완료 뒤 S로 새 랩을 시작하면 유효 기록은 유지합니다. R은 모든 기록까지 지우는 전체 초기화입니다.

**선택 확장:** 베스트 랩, 여러 체크포인트, 파일 저장. 완료 조건에는 포함하지 않습니다.
**이번 범위에서 제외:** 차량 물리·주행 화면·트랙 모델링.

## 핵심 동작 확인

아래 상황을 직접 확인하면 됩니다. 별도 검증 보고서는 필요 없으며, 확인한 결과와 남은 문제를 핵심 설명에 한두 줄로 적습니다. 아래 표는 기대 결과이고 실제 실행 결과가 아닙니다.

| ID | 확인 방법 | 기대 결과 |
|---|---|---|
| L01 | 0초 시작 → 3초 CP1 → 7초 결승 | 구간 3초·4초, 유효 랩 7초 |
| L02 | 시작 → CP1 없이 결승 | 무효 랩 표시, 유효 기록에 추가하지 않음 |
| L03 | 시작 전 CP1·결승 이벤트 | 기록과 상태 변경 없음 |
| L04 | CP1을 두 번 통과 | 첫 통과 시각 유지 |
| L05 | 기록 생성 후 R | 시작 전 상태, 시간·기록 초기화 |

## 작업 방법

1. 원본 저장소를 개인 계정으로 Fork하고 로컬에 복제합니다. 원본 주소를 `upstream`으로 등록합니다. 원격 저장소가 공개되면 실제 주소를 사용합니다.
2. 이 주차 브랜치에서 개인 작업 브랜치를 만듭니다. 다음 명령은 원본을 `upstream`으로 등록한 뒤 실행합니다.

```sh
git fetch upstream
git switch -c work/03 upstream/week/03-lap-timing
```

3. 각자 구현하고 핵심 동작을 확인합니다. 작업 중 Discord에서 질문·화면 공유·토론할 수 있습니다.
4. 코드를 커밋해 개인 Fork에 올리고, 코드·실행 방법·시연·핵심 설명을 README 하나에 모읍니다. 이미 만든 브랜치로 돌아갈 때는 `git switch work/03`를 사용합니다.

```sh
git add <공유할-소스와-문서>
git commit -m "Implement 03-lap-timing study"
git push -u origin work/03
```

## 가벼운 결과 공유

필수 공유물은 다음 세 가지입니다. **추가 보고서·슬라이드·상세 회고는 필요하지 않습니다.**

- 코드와 간단한 실행 방법: 필요한 도구 버전, 프로젝트 열기·빌드·실행 순서, 조작법.
- 짧은 시연: 유효·무효 랩을 각각 보여주는 콘솔 캡처.
- 핵심 설명 3~5줄: 구현 내용, 선택한 방법과 이유, 확인한 동작과 남은 한계.

### 복사할 공유 양식

```text
[03주차 / 레이싱 게임] 이름
- 코드·실행 방법: <개인 Fork의 작업 브랜치 링크>
- 시연: <이미지·영상 또는 콘솔 결과 위치>
- 핵심 설명: <구현 내용 / 선택 이유 / 확인 결과·한계, 3~5줄>
```

### 작성 예시

아래는 작성법을 보여주는 가상 예시이며 실제 구현·검증 결과가 아닙니다.

```text
[03주차 / 레이싱 게임] 민수
- 코드·실행 방법: 개인 Fork의 work/03 브랜치 README
- 시연: README에 첨부한 콘솔 캡처
- 핵심 설명: 시계와 랩 상태를 분리해 0·3·7초 이벤트로 구간 3초·4초를 확인했습니다. CP1을 건너뛴 랩은 기록에서 제외합니다. 실제 차량 이동은 이번 범위에 포함하지 않았습니다.
```

Discord에는 위 자료를 모아 둔 README 링크만 올려도 됩니다. 미완성이면 현재 결과와 막힌 점을 공유합니다. 외부 코드·에셋을 가져왔다면 출처·사용 조건을, AI 도움을 받았다면 도움받은 범위와 직접 확인한 내용을 짧게 덧붙입니다.

## 발표

발표 5분 + 질의응답 5분을 기본으로 **시연 → 핵심 구현과 선택 이유 → 확인 결과·한계**를 이야기합니다. 불참 시에는 기존 결과 게시글로 대체하고 필요한 설명만 보완합니다. 별도 대체 발표 자료는 필수가 아닙니다.

## 저장소에 포함할 것

소스, 솔루션·프로젝트 파일 또는 빌드 설정, 직접 만든 시연 자료를 관리합니다. 사용자별 IDE 설정과 컴파일 결과는 `.gitignore`로 제외합니다.
빌드 결과물·캐시·비밀 키는 올리지 않습니다. 새 환경에서 실행에 필요한 파일은 제외하지 않습니다.
