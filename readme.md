# 03주차 — 레이싱 게임 — 랩·구간 기록

## 1. 이번 주차의 주제

차량 이동 대신 시작·체크포인트·결승선 이벤트로 랩과 구간 시간을 기록합니다. 시간 측정과 유효한 이벤트 순서를 분리합니다.

## 2. 사전 지식

아래 개념·검색어를 따라 개인적으로 학습하고, 확인 질문에 작은 계산·그림·코드로 답할 수 있는지 살펴봅니다. 학습 노트 제출은 필요하지 않습니다. 설계 패턴은 이해를 돕는 수단이며 특정 구조를 강제하지 않습니다.

| 분야 | 학습할 개념·검색어 | 구현과의 연결 | 스스로 확인할 질문 |
|---|---|---|---|
| 수학·물리 | 시간차·단위 변환·구간 합 | 구간은 인접 시각의 차이, 랩은 종료−시작입니다. 차량 동역학은 필요하지 않습니다. | 0초 시작·3초 CP1·7초 완주의 구간과 랩은? |
| 컴퓨터 과학 | 유한 상태 기계·이벤트 순서 | 시작 전·주행·종료 상태와 허용 이벤트를 정합니다. | CP1 누락과 중복 통과를 어떻게 구분할까요? |
| 게임 엔진 원리 | 트리거 이벤트·게임 시간과 실제 시간 | 트리거 콜백을 키 입력으로 대체하고 일시정지가 기록에 포함되는지 구분합니다. | timeScale이 0이어도 실제 시간은 흐를까요? |
| 알고리즘·자료구조 | 체크포인트 배열·다음 인덱스·기록 목록 | 현재 기대하는 체크포인트를 기준으로 순서를 검사합니다. | CP가 늘어날 때 조건문 대신 어떤 데이터로 순서를 표현할까요? |
| 설계 패턴 | 상태 전이·시계 의존성 주입 | 이벤트 시각을 인자로 받으면 실제 대기 없이 결과를 확인할 수 있습니다. | 7초 랩을 실제 7초 기다리지 않고 어떻게 재현할까요? |
| 운영체제 | steady_clock과 달력 시계·스케줄링 | 단조 시계를 사용하고 대기 시간을 정확한 측정값으로 간주하지 않습니다. | 시스템 시간 변경으로 기록이 음수가 될 가능성은? |

## 3. 구현 환경 세팅

환경: **C++ / Windows 콘솔(CMD)**. 이 절은 개인 Fork 복제 후 수행할 설정입니다. 현재 브랜치에는 문서와 `.gitignore`만 있고 소스·프로젝트·Starter Kit는 없습니다. 아래 설정을 마친 뒤 프로젝트와 기능을 구현해야 빌드할 수 있습니다. 사용할 도구의 정확한 버전은 시작 전에 합의합니다.

1. Visual Studio의 **C++를 사용한 데스크톱 개발** 워크로드와 Windows SDK를 설치합니다.
2. Fork 폴더 안에 C++ 콘솔 앱 프로젝트를 만듭니다. 솔루션·프로젝트 파일이 Fork 안에 저장되는지 확인하고 별도 Git 저장소를 중첩 생성하지 않습니다.
3. 프로젝트 속성에서 C++17 이상, 빌드 플랫폼 x64로 설정합니다. 기본 표준 라이브러리 외 외부 패키지는 필요하지 않습니다.
4. 기본 콘솔 프로그램을 빌드·실행한 뒤 주차별 로직을 작성합니다. 실제 사용한 컴파일러·SDK 버전을 프로젝트 설정에 맞춰 확인합니다.

설정 참고: [Visual Studio C++ 개발](https://learn.microsoft.com/en-us/cpp/get-started/?view=msvc-170).

## 4. 기획안과 구현 목표

### 기획 규칙과 범위

- 최소 코스는 시작선 → CP1 → 결승선입니다. S 시작, C 체크포인트, F 결승선, R 재시작, Esc 종료를 기본안으로 합니다.
- 주행 중 결승선을 통과했지만 CP1이 없으면 무효 랩으로 종료합니다. 시작 전 이벤트는 무시하고 이유를 표시합니다. 중복 CP1은 첫 시각을 유지합니다.
- 실행 중에는 단조 증가 시계를 사용하고, 검증 시에는 0·3·7초처럼 지정한 시각을 넣을 수 있는 구조를 권장합니다.
- 완료 뒤 S로 새 랩을 시작하면 유효 기록은 유지합니다. R은 모든 기록까지 지우는 전체 초기화입니다.

**선택 확장:** 베스트 랩, 여러 체크포인트, 파일 저장. 완료 조건에는 포함하지 않습니다.
**이번 범위에서 제외:** 차량 물리·주행 화면·트랙 모델링.

### 구현할 기능

1. 시작·체크포인트·결승선 이벤트를 키보드 입력으로 발생시킵니다.
2. 시작 전·주행 중·완료 상태를 구분하고 랩과 구간 시간을 계산합니다.
3. 체크포인트 순서를 지킨 랩만 유효 기록으로 남깁니다.
4. 재시작 시 진행 상태·현재 시간·기록을 초기화합니다.

### 목표 동작 명세

기획에 따른 기대 결과이며 실제 확인 결과가 아닙니다. 구현하면서 직접 확인하면 되고 별도 검증 보고서는 필요하지 않습니다.

| ID | 확인 방법 | 기대 결과 |
|---|---|---|
| L01 | 0초 시작 → 3초 CP1 → 7초 결승 | 구간 3초·4초, 유효 랩 7초 |
| L02 | 시작 → CP1 없이 결승 | 무효 랩 표시, 유효 기록에 추가하지 않음 |
| L03 | 시작 전 CP1·결승 이벤트 | 기록과 상태 변경 없음 |
| L04 | CP1을 두 번 통과 | 첫 통과 시각 유지 |
| L05 | 기록 생성 후 R | 시작 전 상태, 시간·기록 초기화 |

## 5. 프로젝트 Fork와 세팅 후 빌드

### Fork와 작업 브랜치

1. 원본 GitHub 저장소를 개인 계정으로 Fork합니다. 실제 원본 주소가 정해지면 아래 URL 자리표시자를 바꿉니다.
2. PowerShell에서 다음 명령을 실행합니다. `<...>` 전체를 실제 URL로 바꾸세요. 이미 복제했다면 clone과 remote add를 반복하지 않습니다.

```powershell
git clone <개인-Fork-URL> game-system-lab
cd game-system-lab
git remote add upstream <원본-저장소-URL>
git fetch upstream
git switch -c work/03 upstream/week/03-lap-timing
```

`origin`은 개인 Fork, `upstream`은 원본입니다. 원본에서 주차 브랜치를 가져오므로 Fork에 기본 브랜치만 복사되어 있어도 됩니다. 이미 만든 작업 브랜치로 돌아갈 때는 `git switch work/03`을 사용합니다. 다음으로 3절의 환경을 구성하고 4절의 기능을 구현합니다.

### 빌드와 실행

1. 3절에서 생성하거나 가져온 실제 솔루션 파일을 Visual Studio로 엽니다. 프로젝트를 아직 만들지 않았다면 빌드할 대상이 없습니다.
2. 실행할 프로젝트를 시작 프로젝트로 지정하고 **Debug / x64**를 선택한 뒤 **빌드 → 솔루션 빌드**를 실행합니다.
3. **디버깅하지 않고 시작(Ctrl+F5)**으로 실행합니다. 상태를 추적할 때는 F5로 디버깅하고 중단점에서 값을 확인합니다.
4. 출력 경로는 프로젝트 속성의 출력 디렉터리에서 확인합니다. 소스·솔루션·프로젝트 설정을 함께 관리하고 `.vs/`·중간 생성물·실행 파일은 기존 `.gitignore`로 제외합니다.
5. 콘솔에서 4절의 조작·입력을 사용해 목표 동작을 확인합니다. 입력 대기 중 정지한 상태와 비정상 종료를 구분합니다.
